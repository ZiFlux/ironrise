## 0. Ключевые технические решения

| Решение | Выбор | Почему |
|---|---|---|
| Мобильный клиент | **Flutter (Dart)** | Одна кодовая база под iOS и Android. Свой движок рендеринга подходит для анимированного аватара и боёв. Пакет `health` работает и с Apple Health, и с Health Connect |
| Аватар и анимации | **Rive** (2D, кости и параметры) | Пропорции частей тела задаются параметрами State Machine, их можно двигать прямо из кода. Файлы весят мало, косметика собирается слоями. 3D можно сделать позже |
| Бэкенд | **NestJS (TypeScript) + PostgreSQL**, одним сервисом (монолит), всё в Docker | Вся игровая логика (опыт, антифрод, дуэли) должна считаться на сервере, иначе её подделают. Модули NestJS повторяют модули из ТЗ. Один разработчик не должен поддерживать микросервисы. Redis добавляется, когда понадобится очередь |
| Хостинг | Сначала **один регион**, Docker позволяет переехать. Для беты в РФ: Yandex Cloud. Перед выходом в ЕС: отдельный регион (см. раздел 7) | Пульс относится к данным о здоровье. Для пользователей из РФ данные должны храниться в РФ (152-ФЗ), для ЕС действует GDPR. Поэтому привязываться к Firebase или Supabase как к единственной БД не стоит |
| Платежи | **RevenueCat** (App Store + Google Play) для международных пользователей, позже RuStore Billing для РФ | Одна библиотека закрывает обе платформы и подписки |
| Авторизация | Своя (JWT + refresh), вход по e-mail/телефону, Sign in with Apple, VK ID / Яндекс ID | Sign in with Apple обязателен в iOS, если есть другие соцвходы |
| Пуш-уведомления | FCM + APNs, для RuStore — RuStore Push | |
| Аналитика | AppMetrica | Работает в РФ, есть когорты и удержание: главная метрика продукта |
| Веб-сайт | Next.js (лендинг и публичные профили), позже | Тренировки через сайт не ведутся |
| Админка | Готовая (AdminJS для NestJS) | Справочник упражнений, коэффициенты, модерация, косметика |

**Все игровые коэффициенты** (k_base = 18, порог отставания 1,5, B = 1,5, K_bal 0,9/1,05, лимит серии 30, +24/−12 и т. д.) хранятся в таблице `game_config` и меняются без релиза приложения.

## 1. Архитектура

```
┌────────────────────┐      HealthKit / Health Connect
│  Часы / браслет    │ ───────────────┐
└────────────────────┘                ▼
                           ┌──────────────────────┐
                           │ Flutter-приложение   │  ввод подходов, аватар (Rive),
                           │                      │  бой (проигрывание лога), магазин
                           └─────────┬────────────┘
                                     │ HTTPS / REST + WebSocket (позже)
                           ┌─────────▼────────────┐
                           │  API (NestJS)        │
                           │  ├ accounts          │
                           │  ├ workouts          │
                           │  ├ exercises         │
                           │  ├ antifraud         │──► V ∈ [0;1]
                           │  ├ progression       │──► XP, уровни, баланс, серия
                           │  ├ duels             │──► сила P, симуляция боя, лог
                           │  ├ ranking           │
                           │  ├ shop              │
                           │  └ notifications     │──► очередь (BullMQ + Redis)
                           └─────────┬────────────┘
                              PostgreSQL · Redis · S3 (ассеты)
```

**Основные принципы:**
1. **Сервер решает всё.** Клиент отправляет только сырые данные: подходы, время и пульсовые выборки. Опыт, уровни, V и исход дуэли считает сервер.
2. **Дуэль детерминирована.** Сервер по `seed` и снимкам двух аватаров строит лог ходов (`[{attacker, part, dmg}]`). Клиент только проигрывает его анимацией. Поэтому соперник может быть офлайн, а результат нельзя подменить.
3. **Снимок аватара (snapshot).** На момент дуэли фиксируются уровни, серия и K_bal защитника. Бой воспроизводим, его можно разобрать при жалобе.
4. **Офлайн-режим в зале.** Подходы пишутся в локальную БД (drift/sqlite) и отправляются на сервер после тренировки.

## 2. Пульс и шаги с часов в реальном времени

Живой пульс на экране тренировки входит в MVP. Через Apple Health и Health Connect он не приходит: они отдают сохранённые данные с задержкой. Поэтому используются три канала, которые дополняют друг друга:

| Канал | Устройства | Как работает | Код |
|---|---|---|---|
| **1. Приложение на часах** | Apple Watch | Приложение на часах запускает тренировку и отправляет пульс и шаги на iPhone каждые 1–2 с. С iOS 17 тренировку можно зеркалить с часов на телефон | Swift / SwiftUI |
| | Wear OS (Galaxy Watch, Pixel Watch) | Приложение на часах читает пульс в реальном времени и передаёт на телефон | Kotlin |
| **2. Трансляция пульса по Bluetooth** | Xiaomi, Amazfit, Huawei (часть моделей), Polar, Garmin, Coros, нагрудные датчики | Пользователь включает на часах «трансляцию пульса», телефон ловит её как обычный датчик пульса | Flutter, на часах ничего не ставится |
| **3. Сверка после тренировки** | Всё, что пишет в Apple Health или Health Connect | Если живого пульса не было, приложение забирает записанный пульс после тренировки | Flutter (пакет `health`) |

**Порядок для MVP:** сначала канал 2 и 3 (они пишутся на Flutter и покрывают больше всего устройств), затем приложение для одной из платформ часов, той, что у вас и бета-тестеров. Вторую платформу можно сделать сразу после MVP.

Flutter не умеет собирать приложения для часов, поэтому приложения на часах пишутся отдельно, нативно. Это небольшие приложения: экран «пульс, время, шаги» и передача данных. На каждое уходит примерно 2–3 недели. С телефонным приложением они связываются через platform channels.

Проверка честности тренировки работает со всеми тремя каналами. При живом пульсе (каналы 1 и 2) она точнее: видны циклы «подход — отдых» с точностью до секунды, и их можно сопоставить с моментами, когда пользователь отмечает подход.

## 4. Алгоритмы: как реализовать

Формулы взяты из ТЗ, здесь уточнения для кода.

**4.1 Опыт.** `XP = k_base · d_part · B_part · V` за каждый подход. Уровень = `floor(xp / 100) + 1`. Кардио: `XP_cardio = k_cardio · минуты_в_зоне` (зона 2 и выше по формуле Карвонена от пульса покоя). k_cardio нужно подобрать так, чтобы 30 минут бега ≈ 1 силовой тренировке.

**4.2 Баланс.** Средний уровень считается **после** каждой принятой тренировки. Отстающая часть: `L_i < avg − 1.5`. Кардио учитывается в балансе наравне с остальными, как в ТЗ. Рекомендация «что подкачать»: упражнение из справочника с максимальной долей `d` на отстающую часть, с учётом инвентаря пользователя.

**4.3 Серия и отдых по формату тренировок.** При создании героя пользователь выбирает формат тренировок. Формат задаёт, сколько дней отдыха подряд допустимо:

| Формат | Тренировок в неделю | Допустимо дней отдыха подряд |
|---|---|---|
| Фулбоди | 3 | 2 (например, Пн/Ср/Пт и выходные) |
| Верх / низ | 4 | 2 |
| Сплит | 5–6 | 1 |
| Свой график | пользователь отмечает дни недели (минимум 3) | вычисляется по самому длинному перерыву в графике |

Правила:
- Тренировка или кардио в любой день продлевают серию, даже если день был запланирован как отдых.
- Отдых в пределах лимита формата серию не сбрасывает и тоже продлевает её. Серия считается в днях, а не в тренировках, поэтому человек на 3 тренировках в неделю получает тот же бонус, что и на 6. Награда идёт за регулярность, а не за объём.
- Если отдых длится на 1 день дольше лимита, серия сбрасывается.
- Минимум 3 тренировки в неделю для любого формата, иначе формат «1 раз в неделю» давал бы бесконечную серию.
- Формат можно менять не чаще раза в 7 дней, чтобы не «подстраивать» его под пропуск.

Каждую ночь (по часовому поясу пользователя) cron закрывает день как training / cardio / rest / missed. Можно добавить «заморозку» серии, например 1 в неделю: она только защищает серию и на силу не влияет.

**4.4 Антифрод (MVP, правила).** Коэффициент V считается как произведение проверок:
- нет данных часов → `V = 0.5`, тренировка не идёт в рейтинговые дуэли;
- средний пульс ≤ пульс покоя + 15 → ×0.3;
- нет колебаний «подход — отдых» (низкая дисперсия HR, мало пиков относительно числа подходов) → ×0.6;
- длительность < `число_подходов × 60 с` → ×0.3;
- больше 8 подходов на упражнение: лишние подходы не засчитываются;
- дневной потолок опыта: сверх лимита начисляется 0;
- рост рабочего веса больше чем на 20% от максимума за 4 недели → статус `flagged`, опыт за этот подход заморожен до следующей подтверждённой тренировки с похожим весом.

Пороги лежат в `game_config`. После запуска их нужно откалибровать на реальных данных.

**4.5 Сила и дуэль.** `P = (10·ΣL_i + 2·min(S, 30)) · K_bal`. Бой длится 6–10 ходов. На каждом ходу случайно (по seed) выбирается атакующая часть с весом по её уровню, `dmg = P/20 · (1 + L_part/avgL)/2 · rand(0.85..1.15)`, HP = P. Чтобы победа не была гарантирована при близких силах, нужен небольшой разброс, но перевес 20% должен давать около 85% побед. Это проверяется Монте-Карло-симуляцией перед релизом. Ограничения: не больше N атак в день и не больше 1 атаки на одного соперника в день.

## 4.7 Монетизация и лимиты

Подписка снимает ограничения функционала, но **никогда не даёт преимущества в соревновании** (ТЗ: покупки не влияют на силу).

| Можно продавать в подписке | Нельзя продавать |
|---|---|
| Расширенная аналитика, полная история, экспорт | Снятие лимита 8 подходов на упражнение |
| Авторские программы тренировок | Снятие дневного потолка опыта |
| Больше слотов образов в гардеробе, ранний доступ к косметике | Повышение коэффициента V без часов |
| Платный трек батлпаса (косметика) | Бусты опыта и силы |
| Больше нерейтинговых дуэлей с друзьями в день | Лишние рейтинговые дуэли |

Лимиты в правом столбце защищают честность рейтинга и здоровье новичков.

## 4.8 Удержание: зачем открывать приложение

Тренировка 3 раза в неделю даёт только 3 повода зайти. Нужны поводы на остальные дни и причины не бросить, но без давления на здоровье: отдых по графику не наказывается, потолок опыта в день остаётся, ничего не продаём за прогресс.

**Ближайшее (высокий эффект, небольшой объём):**
1. **Плитка и циферблат на часах (Wear OS Tile).** Серия, сила и день недели «тренировка / отдых» — на циферблате. Человек видит героя десятки раз в день без открытия приложения. Приложение для часов уже есть.
2. **Недельный итог в воскресенье.** Карточка «Неделя: 3 из 3 тренировок, ноги +2 уровня, сила +34» с аватаром «было → стало» и кнопкой «Поделиться» в сторис. Повод зайти и бесплатное привлечение.
3. **Шаги в дни отдыха.** Шаги с часов или Health Connect немного качают кардио (с потолком). Открыть приложение в день отдыха — полезно, но серия от этого не зависит.
4. **Лиги с повышением (Бронза → Серебро → Золото).** Недельная лига уже есть; добавить повышение для лучших и понижение для последних — у Duolingo это главный двигатель возвратов.
5. **Ответ на атаку.** Пуш «Даня атаковал тебя и победил» уже приходит; добавить кнопку «Реванш» прямо в уведомлении.

**Следующее:**
6. **Напарник по серии.** Двое договариваются тренироваться и держат общую серию: если один пропустил неделю, сгорает у обоих. Социальная ответственность работает сильнее напоминаний.
7. **Лента друзей.** «Лиза прокачала спину до 7» с реакцией «кулак». Только события, без тренировок и пульса (приватность).
8. **Возвращение после перерыва.** После пропуска не стыдить, а предложить «квест возвращения»: первая тренировка после паузы — бонус к опыту. Человек, сорвавший серию, — самый вероятный кандидат бросить.
9. **Вехи аватара.** На уровнях 5, 10, 20 у героя новая поза победы и бесплатная вещь; экран «было → стало» с первого дня.
10. **Время напоминания по привычке.** Пуш приходит за час до времени, когда человек обычно тренируется, а не в фиксированное время.

**Позже:** групповая цель для друзей (общая шкала опыта за неделю), соревнование залов и вузов, виджет на экран телефона, сезонные события.

**Чего не делаем:** лутбоксы за деньги, наказание за отдых, пуши чаще одного в день (кроме атак друзей), «потеря прогресса» за неактивность.

## 4.6 Система тренировок (отдельное направление, проектируется позже)

Тема большая, поэтому для неё будет отдельный документ `docs/TRAINING_SYSTEM.md`. До этого приложение строится так, чтобы систему можно было встроить без переделок: программа тренировок — это данные с сервера, а не код.

**Что зафиксировано сейчас:**
- **Аудитория:** новички с проблемами дисциплины. Цель — чтобы тренировки приносили удовольствие, а не изматывали.
- **Старт:** понемногу, 3 раза в неделю, базовые упражнения, умеренная нагрузка. Первые недели лучше недогрузить, чем перегрузить.
- **Прогрессия:** со временем предлагаются более точечные упражнения на отстающие группы. Это связано с контролем баланса из раздела 4.2.
- **Объективная оценка силы:** по весам, которые осиливает пользователь, с учётом его комплекции (вес, рост, пол, возраст) определяется уровень его силовых показателей. Например, через расчётный разовый максимум и сравнение с нормативами для его веса.

**Что заложить в приложение уже сейчас:**
- В профиле: вес, рост, пол, год рождения, опыт тренировок (необязательные поля, заполняются в онбординге).
- История подходов хранится полностью (вес × повторы), чтобы потом пересчитать по ней силовые показатели.
- Таблицы `programs`, `program_days`, `program_exercises` (план тренировок пользователя). В MVP там одна стартовая программа «3 раза в неделю, базовые упражнения».

**Вопросы для отдельного проектирования:** методика оценки силы и источники нормативов, правила прогрессии нагрузки, когда и как предлагать точечные упражнения, защита от перегрузки и травм, связь с игровой прокачкой (чтобы игра не подталкивала новичка к лишнему весу).

## 5. Дизайн

### 5.1 Визуальный стиль
- Тёмная тема по умолчанию: зал, вечер, энергия. Один акцентный цвет (раскалённый металл, оранжево-красный) и второй для кардио.
- Аватар в стилизованном 2D (не реализм): легче менять пропорции и нет проблем с «телесными» стандартами.
- Шесть частей тела закодированы цветом и иконкой одинаково по всему приложению: на аватаре, в итогах и в рекомендациях.
- Крупные кнопки и цифры на экране тренировки: им пользуются потными руками между подходами.

### 5.2 Карта экранов (MVP)

| # | Экран | Содержание |
|---|---|---|
| 1 | Онбординг | Подтверждение 18+, цель, подключение Health, «у меня есть часы?» |
| 2 | Создание героя | Ник, внешность, **формат тренировок и дни недели**, стартовые уровни = 1 |
| 3 | **Главная / Герой** | Аватар, 6 шкал, сила P, серия, баннер «отстаёт: ноги → присед», кнопка «Начать тренировку» |
| 4 | Календарь недели | Тренировка / кардио / отдых / пропуск, серия |
| 5 | **Тренировка** | Таймер, пульс (если есть), выбор упражнения, подходы с «+/−», таймер отдыха |
| 6 | Справочник упражнений | Поиск, фильтр по части тела, доли нагрузки |
| 7 | **Итог тренировки** | Анимация роста частей тела, опыт по частям, level-up, бонус баланса, монеты, V-статус («подтверждено часами») |
| 8 | Друзья | Поиск по нику, ссылка-приглашение, список |
| 9 | **Дуэль** | Выбор соперника → сравнение сил → анимация боя → результат и совет |
| 10 | Рейтинг | Вкладки «Друзья» / «Мой вуз» |
| 11 | Магазин / Гардероб | Косметика за монеты, примерка на аватаре |
| 12 | Профиль и настройки | Устройства, уведомления, приватность, удаление аккаунта |

Главный цикл, который должен проходиться за пару касаний: **Главная → Тренировка → Итог → Дуэль → Рейтинг → Главная**.

### 5.3 Дизайн при одном разработчике
Отдельного дизайнера нет, поэтому:
1. **UI:** берём готовый UI-кит (например, Material 3 с собственной темой) и не рисуем каждый экран в Figma. Wireframes нужны только для четырёх ключевых экранов: 3, 5, 7, 9.
2. **Аватар — единственное, что стоит заказать у иллюстратора или риггера на фрилансе.** Это лицо продукта, и его трудно сделать хорошо самому. ТЗ для исполнителя: стиль, 6 параметров пропорций (плечи, грудь, руки, ноги, пресс, «подтянутость» от кардио), 3–4 анимации боя, слоты для косметики. Формат: файл Rive.
3. Стиль аватара стоит показать 5–10 людям из ЦА, например бета-тестерам, до заказа анимаций.
4. На старте 10–15 косметических предметов, этого хватит.

## 6. Этапы и сроки

Сроки ниже рассчитаны на **одного разработчика на полный день**. При работе по вечерам их нужно умножить примерно на 2. MVP разбит на две части, чтобы как можно раньше дать приложение друзьям в руки.

### Этап 0. Подготовка (2–3 недели)
- Перенос формул из HTML-прототипа в общий модуль игровой логики (TypeScript) с юнит-тестами. Это «источник правды» для сервера.
- **Технический спайк по пульсу:** живой пульс по Bluetooth с реальных часов (свои часы и часы друзей) в тестовом Flutter-экране. Главный технический риск, проверяется первым.
- Каркас Flutter-приложения (go_router, Riverpod, drift, dio) и NestJS (Prisma, миграции), Docker, CI на GitHub Actions.
- Справочник упражнений: первые 50–60 упражнений с долями нагрузки.
- Параллельно: найти иллюстратора для аватара и отдать ему ТЗ (раздел 5.3).

### Этап 1a. Ядро: тренировка → прокачка (≈ 8 недель)

| Недели | Что делаем |
|---|---|
| 1–2 | Аккаунты (e-mail, Apple, Google), 18+, онбординг, создание героя с форматом тренировок |
| 3–4 | Экран тренировки: подходы, офлайн-запись, живой пульс по Bluetooth, сверка через Health |
| 5–6 | Сервер: антифрод v1, опыт, уровни, баланс, серия по формату. Итог тренировки, главная, календарь |
| 7–8 | Аватар в Rive с параметрами, кардио с часов, рекомендации «что подкачать» |

**Результат:** закрытая альфа для вас и друзей. Уже можно тренироваться и качать героя, а данные пульса реальных пользователей помогут откалибровать антифрод.

### Этап 1b. Соревнование (≈ 6–7 недель)

| Недели | Что делаем |
|---|---|
| 1–3 | Приложение для часов (одна платформа, та, что у бета-тестеров), передача пульса и шагов в телефон |
| 4–5 | Друзья, асинхронные дуэли (симуляция на сервере, анимация на клиенте), рейтинг «Друзья» |
| 6–7 | Монеты и косметика за монеты, пуши, простая админка, полировка |

**Итого до MVP:** примерно 16–18 недель на полный день. Каждые 2 недели — сборка в TestFlight и Google Play Internal Testing для друзей.

**Что намеренно отложено после MVP:** рейтинг «Мой вуз» (для международного запуска нужен справочник вузов разных стран), оплата реальными деньгами, вторая платформа часов.

### Этап 1.5. Закрытая бета (3–4 недели)
- 50–150 человек: 2–3 компании друзей из одного зала и одного вуза.
- Метрики: **удержание D7/D30, доля недель с ≥ 3 тренировками**, доля тренировок, подтверждённых часами, число дуэлей на пользователя.
- Калибровка коэффициентов и порогов антифрода, Монте-Карло баланса дуэлей.
- Публикация в App Store, Google Play, RuStore.

### Этап 2 (3–4 месяца после запуска)
Сезоны и лиги, батлпас, оплата реальными деньгами (RevenueCat, затем RuStore для РФ), приложение для второй платформы часов, рейтинг «Мой вуз», команды до 5 человек, совместные тренировки, подписка, лендинг и публичные профили, локализация (EN + RU с первого дня, дальше по спросу).

### Этап 3 (масштаб)
Гильдии и войны кланов, соревнования залов и вузов, подтверждение посещения (QR/гео), камера с ИИ (подсчёт повторов по позе: MediaPipe / ML Kit), партнёрские предложения, другие виды спорта.

## 7. Риски

| Риск | Чем грозит | Что делаем |
|---|---|---|
| Один разработчик | Выгорание, растянутые сроки | MVP разделён на 1a и 1b, есть ранняя альфа для друзей. Аватар отдаётся на фриланс, UI на готовом ките, сервер одним сервисом. Друзья могут взять тестирование, справочник упражнений и контент |
| Живой пульс работает не на всех часах | Часть пользователей без живого пульса | Три канала из раздела 2. Тренировка без живого пульса всё равно засчитывается через сверку Health |
| Данные о здоровье в разных странах (152-ФЗ в РФ, GDPR в ЕС, правила App Store и Google Play) | Штрафы, блокировка, отказ в публикации | Явное согласие на обработку пульса, политика конфиденциальности, удаление аккаунта и данных из приложения. Хранение по регионам продумать до выхода в ЕС. **Перед публичным запуском — консультация юриста**, особенно по передаче данных между РФ и ЕС |
| Оплата для пользователей из РФ: App Store и Google Play не принимают российские карты | Нет дохода от российских пользователей | Международные пользователи платят через RevenueCat. Для РФ — RuStore Billing на Android, на iOS решение позже. В MVP оплаты нет вообще |
| Юрлицо и правообладатель | Сложности с публикацией в сторах, получением денег и патентом | Определиться до публичного запуска: на кого аккаунты разработчика в сторах и в какой стране юрлицо |
| Пользователи без часов | Не могут участвовать в рейтинговых дуэлях, отток | Нерейтинговые дуэли с друзьями для всех. Сделать подключение даже дешёвого браслета ценным |
| Перекачка ради игры, травмы | Репутация, вред | Потолок опыта в день, потолок серии 30, отдых не ломает серию, подсказки о восстановлении |
| Дисбаланс дуэлей (старички непобедимы) | Новички уходят | Подбор соперников по силе ±20%, лиги в Этапе 2 |
| Небольшая аудитория на старте, некого вызывать | Пустые дуэли | Бот-соперники («тени» реальных профилей) на холодный старт |

## 8. Регистрация и патент (параллельно с разработкой)
- **Свидетельство на программу для ЭВМ** подавать после MVP, когда будет рабочий код. Язык Dart (клиент) + TypeScript (сервер), ОС Android, iOS.
- **Патент на способ и систему:** взять для заявки модули антифрода и прогрессии. Стоит рано показать патентному поверенному, до публичной беты (публикация может помешать новизне).
- **Товарный знак «IronRise»:** проверить свободность в ФИПС сейчас, до трат на брендинг.

## 9. Открытые вопросы

1. ~~Прототип~~ — HTML-прототип будет добавлен в папку, формулы сверяются с ТЗ.

7. Кто авторы и правообладатель, в какой стране юрлицо, какой путь регистрации требует конкурс?
8. Кто составит справочник упражнений с долями нагрузки (тренер, спортивный врач)?
