# Бета на VPS: постоянный адрес и HTTPS

Замена бете с компьютера (docs/BETA.md): сервер работает круглосуточно, адрес не меняется,
сертификат HTTPS выпускается и продлевается сам. Всё ставится одной командой с компьютера.

Что внутри (`server/compose.prod.yml`): PostgreSQL, API и Caddy. Наружу открыты только
порты 80 и 443, база и API напрямую из интернета недоступны. Каждую ночь в 03:30 —
резервная копия базы, хранятся 7 последних.

## 1. Что понадобится

- **VPS** с Ubuntu 22.04 или 24.04 в РФ (данные пользователей из РФ должны храниться в РФ, 152-ФЗ).
  Минимум: 1 ядро, 0,6 ГБ памяти, 10 ГБ диска. Под нагрузкой контейнеры занимают ~240 МБ,
  вместе с системой ~500–550 МБ; скрипт установки добавит подкачку 2 ГБ. Если тариф с 1 ГБ
  дороже ненамного — лучше взять его, будет запас.
- **Домен** (например, `ironrise.ru`, ~200 ₽ в год) — Let's Encrypt не выдаёт сертификаты на голый IP.
  Для API хватит поддомена: `api.ironrise.ru`.
- **Вход по SSH-ключу** на сервер под `root`.

## 2. Подготовка (один раз)

1. **SSH-ключ** (если ещё нет), в PowerShell:
   ```powershell
   ssh-keygen -t ed25519
   type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@IP_СЕРВЕРА "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
   ```
   Пароль root спросят один раз (его присылает хостинг). Проверка: `ssh root@IP_СЕРВЕРА` входит без пароля.
2. **DNS**: в панели регистратора домена добавить запись **A** `api` → `IP_СЕРВЕРА`.
   Проверка (может занять до часа): `nslookup api.ironrise.ru` показывает IP сервера.
   Пока DNS не обновился, Caddy не сможет выпустить сертификат.
3. **Ключ Firebase** для пушей уже лежит в `server/secrets/firebase.json` (docs/BETA.md) —
   скрипт сам скопирует его на сервер.

## 3. Первый запуск

Из папки `server` в PowerShell:

```powershell
.\deploy\push.ps1 -Server root@IP_СЕРВЕРА -Domain api.ironrise.ru
```

Скрипт соберёт образ API здесь (на сервере с 0,6 ГБ памяти сборка не поместится),
скопирует его, подготовит сервер (Docker, подкачка, файрвол, резервные копии), создаст
`/opt/ironrise/.env.prod` со случайными паролями и запустит всё. Первый раз — 10–20 минут,
дольше всего копирование образа (~300 МБ).

Проверка: `https://api.ironrise.ru/health` в браузере отвечает `{"status":"ok"}`.

## 4. Перенос данных с беты на компьютере

Чтобы тестеры не потеряли аккаунты, героев, друзей и лиги — когда VPS уже работает
и бета на компьютере ещё запущена:

```powershell
.\deploy\migrate-beta.ps1 -Server root@IP_СЕРВЕРА
```

База на VPS **заменяется** копией беты (поэтому делать это до того, как тестеры начнут
пользоваться новым адресом). Пароли и токены входа сохраняются: тестерам не нужно
входить заново, только сменить адрес сервера.

## 5. Переключить приложение

- **Новая сборка для тестеров** — адрес теперь постоянный:
  ```powershell
  flutter build apk --release --dart-define=API_URL=https://api.ironrise.ru --dart-define-from-file=firebase.json
  ```
- **У тех, кто уже установил**: Профиль → Аккаунт и синхронизация → «Сервер: …» →
  `https://api.ironrise.ru`. Вход сохраняется.
- После этого бету на компьютере можно остановить: `docker compose -p ironrise-beta stop`
  (данные останутся в томе на случай отката).

## 6. Обновления

После изменений в коде сервера — та же команда, что в разделе 3. База и пароли не трогаются,
миграции базы применяются сами при старте нового API. Простой — несколько секунд.

## 7. Резервные копии

Лежат на сервере в `/opt/ironrise/backups/ironrise-ГГГГ-ММ-ДД.dump`, 7 последних дней.
Журнал: `/var/log/ironrise-backup.log`.

**Скопировать к себе** (стоит делать раз в неделю: копия на том же сервере не спасёт,
если пропадёт сам сервер):

```powershell
scp root@IP_СЕРВЕРА:/opt/ironrise/backups/ironrise-*.dump .
```

**Восстановить** копию на сервере (данные после момента копии пропадут):

```bash
cd /opt/ironrise
docker compose -f compose.prod.yml --env-file .env.prod stop api
docker compose -f compose.prod.yml --env-file .env.prod exec -T db \
  pg_restore -U ironrise -d ironrise --clean --if-exists --no-owner < backups/ironrise-ГГГГ-ММ-ДД.dump
docker compose -f compose.prod.yml --env-file .env.prod start api
```

## 8. Если что-то не так

На сервере (`ssh root@IP_СЕРВЕРА`, затем `cd /opt/ironrise`):

| Что | Команда |
|---|---|
| Что запущено | `docker compose -f compose.prod.yml --env-file .env.prod ps` |
| Логи API | `docker compose -f compose.prod.yml --env-file .env.prod logs --tail 100 api` |
| Логи HTTPS (сертификат) | `docker compose -f compose.prod.yml --env-file .env.prod logs --tail 50 caddy` |
| Память и диск | `free -h` и `df -h` |
| Перезапустить всё | `docker compose -f compose.prod.yml --env-file .env.prod restart` |

Частые причины: сертификат не выпускается — DNS ещё не указывает на сервер или порт 80
закрыт в панели хостинга; API перезапускается по кругу — смотреть логи API
(например, ошибка в `.env.prod`).
