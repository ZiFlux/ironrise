# IronRise: релиз в Google Play

Приложение для телефона (`app/`) и для часов (`watch/wearos/`) публикуются как **одно приложение** `com.ironrise.ironrise` в Google Play: телефон и часы — разные форм-факторы одной карточки.

## 1. Ключ загрузки

Создан 11 ноября 2026, лежит **вне репозитория**:

```
C:\Users\ziflux\.ironrise\upload-keystore.jks   — ключ
C:\Users\ziflux\.ironrise\key.properties        — пароль и путь к ключу
```

- **Сделайте резервную копию папки `.ironrise`** в надёжное место (облако с шифрованием, менеджер паролей). Не коммитьте её в git и никому не отправляйте.
- При потере ключа загрузки его можно сбросить через поддержку Google Play, если включена **Play App Signing** (по умолчанию включена для новых приложений). Финальную подпись тогда хранит Google.
- Обе сборки (`app/android/app/build.gradle.kts`, `watch/wearos/app/build.gradle.kts`) читают этот файл сами. Если его нет, релиз подписывается отладочным ключом.

> Телефон и часы обмениваются данными, только если подписаны **одним** ключом. Отладочная сборка на часах + релизная на телефоне (или наоборот) не увидят друг друга. После установки из Google Play обе подписаны ключом Google и работают вместе.

## 2. Сборка

```
# телефон
cd app
flutter build appbundle
# → app/build/app/outputs/bundle/release/app-release.aab

# часы
cd watch/wearos
gradlew.bat bundleRelease
# → watch/wearos/app/build/outputs/bundle/release/app-release.aab
```

Версии: телефон — `version:` в `app/pubspec.yaml` (`1.0.0+1`: код версии после `+`). Часы — `versionCode` в `watch/wearos/app/build.gradle.kts`, начинается с 1 000 001. Коды версий телефона и часов не должны совпадать, и каждый новый релиз должен иметь код больше предыдущего.

## 3. Google Play Console (делаете вы)

1. **Аккаунт разработчика**: play.google.com/console, разовый взнос 25 $. Для личного аккаунта нужна проверка личности.
2. **Создать приложение** IronRise, язык по умолчанию — русский.
3. **Политика конфиденциальности**: нужна публичная ссылка. Текст — `docs/PRIVACY.md`. Перед публикацией заполните поля в квадратных скобках (оператор данных, e-mail, страна сервера) и покажите юристу. Варианты размещения: GitHub Pages, страница на сайте IronRise, Google Sites.
4. **Безопасность данных (Data safety)**: собираются e-mail, данные о здоровье (пульс, шаги), фитнес-данные (тренировки), игровая активность, идентификатор устройства для push. Данные шифруются при передаче (HTTPS), пользователь может удалить аккаунт в приложении.
5. **Health Connect**: заполнить декларацию доступа к данным о здоровье (Policy → App content → Health apps) — какие типы читаем (пульс, шаги, расстояние) и зачем.
6. **Foreground service** на часах: декларация типа `health` (пульс во время тренировки).
7. **Возрастной рейтинг**: анкета; приложение 18+ по нашей политике.
8. **Wear OS**: Настройки → Advanced settings → Form factors → добавить Wear OS, загрузить AAB часов в отдельный трек Wear OS, приложить скриншоты часов.
9. **Закрытое тестирование**: новые личные аккаунты обязаны провести закрытый тест — **не меньше 12 тестировщиков в течение 14 дней** — прежде чем открыть продакшен. Это и есть бета для друзей: добавьте их e-mail в список тестировщиков.

## 4. Перед каждым релизом

- `flutter analyze`, `flutter test`, тесты сервера (`npx jest` в `server/`).
- Поднять код версии телефона и часов.
- Если менялась схема БД — применить миграции на сервере до выхода приложения.
